Spring Core

Fundament ekosystemu Spring — Inversion of Control, Dependency Injection i kontener IoC. Zrozumienie tych mechanizmów to klucz do całego Spring Framework.

Spring 6 Poziom: Średnio­zaawansowany

Inversion of Control (IoC)

Tradycyjnie to kod tworzy swoje zależności. W IoC framework przejmuje kontrolę nad tworzeniem i wstrzykiwaniem zależności. Twój kod opisuje czego potrzebuje, a Spring to dostarcza.

Tradycyjne podejście 
public class ZamowienieSerwis {
    // ❌ Klasa SAMA tworzy zależności
    private EmailSerwis email = new EmailSerwis();
    private PlatnoscSerwis platnosc = new PlatnoscSerwis();

    // Problemy:
    // - ścisłe powiązanie (tight coupling)
    // - niemożliwe do przetestowania (nie można podmienić mockiem)
    // - nie można zmienić implementacji bez edycji tej klasy
}
Spring IoC — kontener zarządza 
@Service
public class ZamowienieSerwis {
    private final NotyfikacjaSerwis notyfikacja;
    private final PlatnoscSerwis platnosc;

    // ✅ Spring WSTRZYKUJE zależności przez konstruktor
    public ZamowienieSerwis(
            NotyfikacjaSerwis notyfikacja,
            PlatnoscSerwis platnosc) {
        this.notyfikacja = notyfikacja;
        this.platnosc = platnosc;
    }

    public void zloz(Zamowienie z) {
        platnosc.przetworz(z);
        notyfikacja.wyslij("Zamówienie złożone");
    }
}
// Spring sam znajdzie NotyfikacjaSerwis i PlatnoscSerwis
// i przekaże je do konstruktora — nie musisz pisać new!

Bean to obiekt zarządzany przez kontener Spring. Adnotacje mówią Springowi, które klasy mają być beanami i jaką rolę pełnią.

Dependency Injection — Trzy Sposoby

Constructor vs Field vs Setter Injection 
// ✅ 1. Constructor Injection — REKOMENDOWANY
@Service
public class ProduktSerwis {
    private final ProduktRepo repo;  // final = niemutowalne po init

    public ProduktSerwis(ProduktRepo repo) {
        this.repo = repo;
    }
    // Zalety: niemutowalny, łatwy do testowania, wyraźne zależności
    // Jeśli jest JEDNA zależność, @Autowired zbędny (Spring 4.3+)
}

// ⚠️ 2. Field Injection — popularne, ale nie zalecane
@Service
public class ProduktSerwis {
    @Autowired
    private ProduktRepo repo;  // nie jest final!
    // Wada: nie da się przetestować bez kontenera Spring
}

// 3. Setter Injection — dla opcjonalnych zależności
@Service
public class ProduktSerwis {
    private ProduktRepo repo;

    @Autowired
    public void setRepo(ProduktRepo repo) { this.repo = repo; }
}
✅
Zawsze preferuj Constructor Injection. Zależności są widoczne, niemutowalne i klasa jest łatwa do testowania bez kontenera Spring — wystarczy new MojaKlasa(mockRepo).

Scope Beanów

Bean Scopes 
// Singleton — domyślny: jedna instancja na cały kontener
@Service  // = @Scope("singleton")
public class KonfigSerwis { }

// Prototype — nowa instancja przy każdym pobraniu z kontenera
@Component
@Scope("prototype")
public class RaportGenerator { }

// Request — jedna instancja na żądanie HTTP (tylko web)
@Component
@Scope("request")
public class RequestContext { }

// Session — jedna instancja na sesję HTTP
@Component
@Scope("session")
public class KoszykSesji { }

Konfiguracja przez @Configuration i @Bean

Konfiguracja Java 
@Configuration
public class AppConfig {

    // @Bean — Spring zarządza obiektem zwróconym przez tę metodę
    @Bean
    public ObjectMapper objectMapper() {
        var mapper = new ObjectMapper();
        mapper.configure(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS, false);
        mapper.registerModule(new JavaTimeModule());
        return mapper;
    }

    // Zależności między @Bean — Spring wstrzykuje automatycznie
    @Bean
    public RestTemplate restTemplate(ObjectMapper mapper) {
        var rt = new RestTemplate();
        // konfiguruj z mapperem...
        return rt;
    }
}

// @Conditional — bean tworzony tylko gdy warunek spełniony
@Bean
@ConditionalOnProperty(name = "feature.cache.enabled", havingValue = "true")
public CacheSerwis cacheSerwis() {
    return new RedisCacheSerwis();
}

AOP — Aspect Oriented Programming

AOP pozwala wydzielić przekrojowe zagadnienia (logging, transakcje, security) poza klasę biznesową. Spring AOP działa przez proxy — "opakowanie" wokół twojego beana.

Aspect — logowanie czasu wykonania 
@Aspect
@Component
public class LoggingAspect {

    private static final Logger log = LoggerFactory.getLogger(LoggingAspect.class);

    // @Around — otacza wywołanie metody (przed i po)
    // Pointcut: wszystkie metody w pakiecie service
    @Around("execution(* com.example.service.*.*(..))")
    public Object logCzasWykonania(ProceedingJoinPoint pjp) throws Throwable {
        long start = System.currentTimeMillis();
        try {
            return pjp.proceed(); // wywołaj oryginalną metodę
        } finally {
            long czas = System.currentTimeMillis() - start;
            log.info("{}.{}() — {}ms",
                pjp.getTarget().getClass().getSimpleName(),
                pjp.getSignature().getName(),
                czas);
        }
    }

    // @Before — przed wywołaniem metody
    @Before("@annotation(com.example.RequiresAdmin)")
    public void sprawdzUprawnienia(JoinPoint jp) {
        // sprawdź czy użytkownik ma rolę ADMIN
    }
}
