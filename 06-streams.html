Streams, Lambdy
& Optional

Programowanie funkcyjne w Javie 8+. Stream API pozwala przetwarzać kolekcje deklaratywnie, zwięźle i wydajnie — z opcją równoległego przetwarzania.

Wyrażenia Lambda

Lambda to skrócona forma anonimowej klasy implementującej interfejs funkcyjny (interfejs z jedną metodą abstrakcyjną). Składnia: (parametry) -> { ciało }.

Lambda — ewolucja składni
// Przed Java 8 — anonimowa klasa
Comparator<String> comp1 = new Comparator<>() {
    public int compare(String a, String b) { return a.compareTo(b); }
};

// Java 8+ — lambda
Comparator<String> comp2 = (a, b) -> a.compareTo(b);

// Java 8+ — referencja do metody (jeszcze krócej!)
Comparator<String> comp3 = String::compareTo;

// Wbudowane interfejsy funkcyjne (java.util.function)
Predicate<String> czyDlugi = s -> s.length() > 5;
Function<String, Integer> dlugosc = String::length;
Consumer<String> drukuj = System.out::println;
Supplier<List<String>> nowaLista = ArrayList::new;
BiFunction<Integer, Integer, Integer> suma = Integer::sum;

Pipeline Stream API

Stream przetwarza dane w potoku: source → operacje pośrednie → operacja terminalna. Operacje pośrednie są leniwe — nie wykonują się aż do operacji terminalnej.

Stream Pipeline — kompletny przykład
record Pracownik(String imie, String dzial, double pensja) {}

List<Pracownik> pracownicy = List.of(
    new Pracownik("Anna",  "IT", 8500),
    new Pracownik("Bartek","IT", 9200),
    new Pracownik("Celina","HR", 6100),
    new Pracownik("Dawid", "HR", 6800),
    new Pracownik("Ewa",   "IT", 7700)
);

// 1. Imiona pracowników IT posortowane malejąco po pensji
List<String> itNajlepsi = pracownicy.stream()
    .filter(p -> p.dzial().equals("IT"))
    .sorted(Comparator.comparingDouble(Pracownik::pensja).reversed())
    .map(Pracownik::imie)
    .toList(); // Java 16+ — [Bartek, Anna, Ewa]

// 2. Średnia pensja w firmie
double srednia = pracownicy.stream()
    .mapToDouble(Pracownik::pensja)
    .average()
    .orElseThrow();

// 3. Grupowanie po dziale
Map<String, List<Pracownik>> poDziale = pracownicy.stream()
    .collect(Collectors.groupingBy(Pracownik::dzial));

// 4. Suma pensji per dział
Map<String, Double> sumaPerDzial = pracownicy.stream()
    .collect(Collectors.groupingBy(
        Pracownik::dzial,
        Collectors.summingDouble(Pracownik::pensja)
    ));

// 5. Czy wszyscy w IT zarabiają powyżej 7000?
boolean wszyscyDobrze = pracownicy.stream()
    .filter(p -> p.dzial().equals("IT"))
    .allMatch(p -> p.pensja() > 7000); // false (Ewa ma 7700 > 7000 ✓, ale sprawdź Annę)

// 6. flatMap — spłaszczanie
List<List<Integer>> zagniezdzone = List.of(
    List.of(1,2), List.of(3,4), List.of(5)
);
List<Integer> plaskie = zagniezdzone.stream()
    .flatMap(Collection::stream)
    .toList(); // [1, 2, 3, 4, 5]
⚠️
Stream można użyć tylko raz! Po operacji terminalnej stream jest wyczerpany. Chcesz przetworzyć ponownie? Stwórz nowy stream z kolekcji. Operacje pośrednie są leniwe — nie wykonują się bez terminala.

Optional — eliminacja NullPointerException

Optional — dobre praktyki
// ❌ Tradycyjnie — ryzyko NPE
Uzytkownik u = repo.znajdz(id); // może zwrócić null!
System.out.println(u.getImie()); // NPE jeśli u == null

// ✅ Z Optional — bezpieczne i deklaratywne
// Metoda zwraca Optional<Uzytkownik>
Optional<Uzytkownik> opt = repo.znajdz(id);

// Różne sposoby wyciągnięcia wartości
opt.ifPresent(u -> System.out.println(u.getImie()));   // jeśli istnieje
String imie = opt.map(Uzytkownik::getImie)
                  .orElse("Anonim");                    // wartość domyślna
Uzytkownik u2 = opt.orElseThrow(                       // wyjątek gdy brak
    () -> new EntityNotFoundException("id=" + id));

// Łańcuch operacji — jak Stream
String email = opt
    .filter(Uzytkownik::isAktywny)
    .map(Uzytkownik::getEmail)
    .map(String::toLowerCase)
    .orElse("brak@email.com");

// ❌ ANTY-WZORZEC — nigdy tak!
if (opt.isPresent()) { opt.get(); } // to samo co null-check...
✅
Kiedy używać Optional? Jako typ zwracany z metod, które mogą nie znaleźć wartości (np. metody repo). Nie jako pola klas, nie w parametrach metod.

Parallel Streams

Parallel Stream
// Równoległe przetwarzanie — jedyna zmiana to parallelStream()
long suma = LongStream.rangeClosed(1, 1_000_000)
    .parallel()
    .sum(); // automatycznie na wielu rdzeniach!

// ⚠️ Uważaj: parallel nie zawsze szybszy!
// Opłacalny dla: dużych danych (>10k), drogie operacje CPU,
// operacje bez efektów ubocznych (pure functions)
// Nieopłacalny dla: małych kolekcji, I/O, operacji z synchronizacją
