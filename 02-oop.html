Programowanie Obiektowe

Klasy, obiekty, cztery filary OOP — enkapsulacja, dziedziczenie, polimorfizm, abstrakcja. Interfejsy i kiedy je stosować zamiast dziedziczenia.

Java 8–21 Poziom: Podstawowy

Klasa i Obiekt

Klasa to szablon (blueprint). Obiekt to instancja klasy — konkretna realizacja szablonu w pamięci. Jedna klasa może mieć nieskończenie wiele obiektów.

Konto.java 
public class Konto {

    // Pola (fields) — stan obiektu
    private final String numer;     // final = niemutowalne
    private double saldo;

    // Konstruktor — wywołany przy new Konto(...)
    public Konto(String numer, double saldobPoczatkowe) {
        this.numer = numer;
        this.saldo = saldobPoczatkowe;
    }

    // Metody (methods) — zachowanie obiektu
    public void wplac(double kwota) {
        if (kwota <= 0) throw new IllegalArgumentException("Kwota > 0");
        saldo += kwota;
    }

    public void wyplac(double kwota) {
        if (kwota > saldo) throw new IllegalStateException("Brak środków");
        saldo -= kwota;
    }

    // Getter — dostęp do prywatnego pola
    public double getSaldo() { return saldo; }
    public String getNumer()  { return numer; }
}

// Tworzenie obiektów
Konto k1 = new Konto("PL001", 1000.0);
Konto k2 = new Konto("PL002", 500.0);
k1.wplac(200.0);
System.out.println(k1.getSaldo()); // 1200.0

Enkapsulacja

Ukrywanie wewnętrznego stanu obiektu i udostępnianie go tylko przez kontrolowany interfejs (metody). Zapobiega niespójności danych.

💡
Zasada minimum uprawnień — pola zawsze private. Modyfikatory dostępu: private (tylko klasa) → package-private (pakiet) → protected (pakiet + podklasy) → public (wszędzie).

Dziedziczenie

Pozwala klasie podrzędnej przejąć pola i metody klasy bazowej (extends). Java obsługuje tylko pojedyncze dziedziczenie klas — klasa może rozszerzać tylko jedną klasę.

Dziedziczenie 
public abstract class Pojazd {
    protected String marka;
    protected int rok;

    public Pojazd(String marka, int rok) {
        this.marka = marka;
        this.rok = rok;
    }

    // Metoda abstrakcyjna — podklasy MUSZĄ ją zaimplementować
    public abstract String rodzajNapedu();

    // Metoda konkretna — podklasy mogą nadpisać
    public String info() {
        return marka + " (" + rok + ") — " + rodzajNapedu();
    }
}

public class Samochod extends Pojazd {
    private int pojemnoscSilnika;

    public Samochod(String marka, int rok, int pojemnosc) {
        super(marka, rok);   // wywołanie konstruktora rodzica
        this.pojemnoscSilnika = pojemnosc;
    }

    @Override
    public String rodzajNapedu() {
        return "silnik spalinowy " + pojemnoscSilnika + "cc";
    }
}

public class SamochodElektryczny extends Pojazd {
    private int zasiegKm;

    public SamochodElektryczny(String marka, int rok, int zasieg) {
        super(marka, rok);
        this.zasiegKm = zasieg;
    }

    @Override
    public String rodzajNapedu() {
        return "elektryczny, zasięg " + zasiegKm + "km";
    }
}

Polimorfizm

Ten sam kod działa z różnymi typami obiektów. Metoda wywoływana jest zgodnie z rzeczywistym typem obiektu w czasie wykonania (dynamic dispatch), nie typem zmiennej.

Polimorfizm 
List<Pojazd> pojazdy = new ArrayList<>();
pojazdy.add(new Samochod("Toyota", 2022, 1600));
pojazdy.add(new SamochodElektryczny("Tesla", 2023, 500));

// Każdy pojazd odpowiada swoją implementacją rodzajNapedu()
for (Pojazd p : pojazdy) {
    System.out.println(p.info());
}
// Toyota (2022) — silnik spalinowy 1600cc
// Tesla (2023) — elektryczny, zasięg 500km

// Pattern Matching instanceof (Java 16+) — eleganckie rzutowanie
for (Pojazd p : pojazdy) {
    if (p instanceof SamochodElektryczny el) {
        System.out.println("Zasięg: " + el.zasiegKm + "km");
        // el jest już rzutowany — nie trzeba castować osobno
    }
}

Interfejsy

Interfejs definiuje kontrakt — co obiekt potrafi, bez informacji jak to robi. Klasa może implementować wiele interfejsów (w odróżnieniu od dziedziczenia). Od Java 8 interfejsy mogą mieć metody default i static.

Interfejsy 
// Interfejs — tylko kontrakt
public interface Drukowalny {
    void drukuj();
}

public interface Exportowalny {
    byte[] eksportuj();

    // Metoda default — implementacja w interfejsie (Java 8+)
    default String formatNazwy() {
        return this.getClass().getSimpleName() + "-eksport";
    }
}

// Klasa może implementować WIELE interfejsów
public class Faktura implements Drukowalny, Exportowalny {
    private final String numer;

    @Override
    public void drukuj() {
        System.out.println("Faktura: " + numer);
    }

    @Override
    public byte[] eksportuj() {
        return numer.getBytes();
    }
}

// Interfejsy funkcyjne — z jedną metodą abstrakcyjną
@FunctionalInterface
public interface Walidator<T> {
    boolean waliduj(T wartosc);
}

// Implementacja jako lambda
Walidator<String> emailValidator = s -> s.contains("@") && s.contains(".");
System.out.println(emailValidator.waliduj("jan@example.com")); // true
⚠️
Interfejs vs Klasa abstrakcyjna — użyj interfejsu gdy chcesz zdefiniować kontrakt wielokrotnego użytku i możliwość wielokrotnej implementacji. Użyj klasy abstrakcyjnej gdy klasy pochodne powinny dzielić implementację i stan (pola).

Sealed Classes (Java 17+)

Sealed classes ograniczają, które klasy mogą rozszerzać daną klasę lub interfejs. Kompilator może wtedy weryfikować kompletność obsługi wszystkich przypadków.

Java 17+ 
public sealed interface Wynik<T>
    permits Sukces, Blad {}

public record Sukces<T>(T wartosc) implements Wynik<T> {}
public record Blad<T>(String komunikat) implements Wynik<T> {}

// Pattern matching switch — kompilator weryfikuje kompletność
Wynik<Integer> wynik = oblicz(10, 0);
String komunikat = switch (wynik) {
    case Sukces<Integer>(var v) -> "Wynik: " + v;
    case Blad<Integer>(var msg) -> "Błąd: " + msg;
}; // brak default — kompilator wie, że pokryliśmy wszystko
