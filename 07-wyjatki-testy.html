Wyjątki & Testy

Solidna obsługa błędów i automatyczne testy jednostkowe to podstawa profesjonalnego kodu. JUnit 5 + Mockito to standard w Javie.

JUnit 5 Poziom: Podstawowy

Hierarchia Wyjątków

Wszystko zaczyna się od Throwable. Checked exceptions muszą być obsłużone lub deklarowane w sygnaturze metody. Unchecked (podklasy RuntimeException) — nie muszą, ale warto je dokumentować.

Hierarchia
Throwable
├── Error                    // Błędy JVM — nigdy nie łap!
│   ├── OutOfMemoryError
│   └── StackOverflowError
└── Exception
    ├── Checked Exceptions      // Kompilator wymaga obsługi
    │   ├── IOException
    │   └── SQLException
    └── RuntimeException        // Unchecked
        ├── NullPointerException
        ├── IllegalArgumentException
        └── IndexOutOfBoundsException

Dobre Praktyki Obsługi Wyjątków

Wyjątki — co robić, czego nie robić
// ✅ try-with-resources — AutoCloseable zamknięty automatycznie
try (var reader = new BufferedReader(new FileReader(plik))) {
    String linia = reader.readLine();
} catch (IOException e) {
    log.error("Błąd odczytu: {}", plik.getName(), e);
    throw new PlikNieOdczytalnyException("Nie można odczytać: " + plik, e);
}

// ✅ Multi-catch — Java 7+ (jeden handler dla kilku typów)
try {
    ryzykownaOperacja();
} catch (IOException | SQLException e) {
    log.error("Błąd I/O lub DB", e);
}

// ✅ Własny wyjątek z kontekstem
public class UzytkownikNieIstnieje extends RuntimeException {
    private final long userId;
    public UzytkownikNieIstnieje(long id) {
        super("Użytkownik id=" + id + " nie istnieje");
        this.userId = id;
    }
}

// ❌ Anty-wzorce
catch (Exception e) {}                   // — połykanie wyjątków
catch (Exception e) { e.printStackTrace(); } // — używaj loggera

Testy Jednostkowe — JUnit 5

Dobry test składa się z trzech bloków: Arrange (przygotuj dane), Act (wywołaj testowany kod), Assert (sprawdź wynik). Adnotacja @ExtendWith(MockitoExtension.class) włącza Mockito.

JUnit 5 + Mockito
@ExtendWith(MockitoExtension.class)
class ZamowienieSerwisTest {

    @Mock private UzytkownikRepo uzytkownikRepo;
    @Mock private PlatnoscSerwis platnoscSerwis;
    @InjectMocks private ZamowienieSerwis sut;

    @Test
    @DisplayName("Powinien złożyć zamówienie gdy użytkownik istnieje")
    void powinienZlozycZamowienie() {
        // Arrange
        var uzytkownik = new Uzytkownik(1L, "Anna");
        when(uzytkownikRepo.znajdz(1L)).thenReturn(Optional.of(uzytkownik));
        when(platnoscSerwis.przetworz(anyDouble())).thenReturn(true);

        // Act
        Zamowienie wynik = sut.zloz(1L, 299.99);

        // Assert
        assertNotNull(wynik);
        assertEquals(Status.POTWIERDZONE, wynik.getStatus());
        verify(platnoscSerwis).przetworz(299.99);
    }

    @ParameterizedTest
    @ValueSource(doubles = {-1, 0, -999})
    void powinienOdrzucicNieprawidlowaKwote(double kwota) {
        assertThrows(IllegalArgumentException.class,
            () -> sut.zloz(1L, kwota));
    }
}

Cykl życia Testu — @Before / @After

JUnit 5 oferuje adnotacje do kodu współdzielonego między testami. @BeforeEach i @AfterEach działają per metoda testowa, @BeforeAll i @AfterAll — raz na klasę (metoda musi być static).

Cykl życia JUnit 5
class ProduktSerwisTest {

    private ProduktSerwis serwis;

    @BeforeAll
    static void inicjalizujBaze() {
        // wywołane raz przed wszystkimi testami w klasie
    }

    @BeforeEach
    void setup() {
        serwis = new ProduktSerwis(new InMemoryProduktRepo());
        // wywołane przed KAŻDym testem
    }

    @AfterEach
    void czyscenie() {
        // wywołane po każdym teście
    }

    @AfterAll
    static void zamknijBaze() {
        // wywołane raz po wszystkich testach
    }

    @Test
    void powinienDodacProdukt() {
        serwis.dodaj(new Produkt("Kawa", 12.50));
        assertEquals(1, serwis.liczba());
    }
}

Asercje — co sprawdzamy

JUnit 5 Assertions + AssertJ
// JUnit 5 — podstawowe asercje
assertEquals("oczekiwane", wynik);
assertNotNull(obiekt);
assertTrue(warunek);
assertFalse(warunek);
assertThrows(IllegalArgumentException.class, () -> sut.metoda(null));
assertTimeout(Duration.ofSeconds(1), () -> sut.szybkaOperacja());

// assertAll — wszystkie asercje sprawdzone, nawet jeśli pierwsza padnie
assertAll(
    () -> assertEquals("Jan", user.getImie()),
    () -> assertEquals("Kowalski", user.getNazwisko()),
    () -> assertTrue(user.isAktywny())
);

// AssertJ — płynne, czytelne asercje (zalecane)
assertThat(wynik).isEqualTo("oczekiwane");
assertThat(lista).hasSize(3).contains("Anna").doesNotContain("Zbyszek");
assertThat(liczba).isBetween(1, 100);
assertThatThrownBy(() -> sut.metoda(null))
    .isInstanceOf(IllegalArgumentException.class)
    .hasMessageContaining("null");
💡
Reguła AAA (Arrange-Act-Assert) — każdy test powinien mieć trzy wyraźne bloki. Jeden test sprawdza jedną rzecz. Nazwa testu to dokumentacja: powinienRzucicWyjatek_gdy_kwotaUjemna().
