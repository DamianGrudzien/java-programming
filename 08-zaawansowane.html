Java 21 Poziom: Zaawansowany

Jak działa JVM

Java Virtual Machine to silnik wykonujący kod. Kompilator javac produkuje bytecode (.class), który JVM tłumaczy na instrukcje natywne przez JIT Compiler.

Pamięć JVM
Heap (sterta) — obiekty i tablice
├── Young Generation — nowe obiekty, szybkie GC (Minor GC)
│   ├── Eden Space       — nowo tworzone
│   ├── Survivor S0      }
│   └── Survivor S1      } — przeżyłe Eden
└── Old Generation (Tenured) — długożyjące, Major GC (wolniejszy)

Metaspace (poza heap, Java 8+) — metadane klas
Stack — ramki metod, zmienne lokalne, referencje (per thread)
Program Counter — adres bieżącej instrukcji (per thread)

// Flagi JVM — dostrajanie GC
// G1GC — domyślny Java 9+, balans latency/throughput
java -XX:+UseG1GC -Xms512m -Xmx4g MyApp

// ZGC — ultra-niskie latency <1ms (Java 15+)
java -XX:+UseZGC MyApp

// Diagnostyka
java -Xlog:gc* -XX:+PrintGCDetails MyApp

Wielowątkowość & Thread Safety

🧵 Podstawy wielowątkowości
▼
Thread & ExecutorService
// 1. Thread — prymityw (unikaj bezpośrednio)
Thread t = new Thread(() -> System.out.println("Hello!"));
t.start();

// 2. ExecutorService — zarządzany pul wątków
try (var executor = Executors.newFixedThreadPool(4)) {
    Future<String> future = executor.submit(() -> pobierzDane());
    String wynik = future.get(); // blokuje wątek!
}

// 3. CompletableFuture — asynchroniczne, bez blokowania
CompletableFuture.supplyAsync(() -> pobierzDane())
    .thenApply(String::toUpperCase)
    .thenAccept(System.out::println)
    .exceptionally(e -> { log.error("Błąd", e); return null; });
🔒 Synchronizacja i thread safety
▼
Thread Safety patterns
// 1. Immutability — najlepsza gwarancja thread safety
public final class ImmutableConfig {
    private final String host;   // final = niezmienne po konstruktorze
    private final int port;
    public ImmutableConfig(String h, int p) { host=h; port=p; }
    public String host() { return host; }
    public int port() { return port; }
}

// 2. AtomicInteger — lockless counter
private final AtomicInteger licznik = new AtomicInteger(0);
licznik.incrementAndGet(); // atomowe!
licznik.compareAndSet(5, 10); // CAS — Compare And Swap

// 3. synchronized — prosta synchronizacja (może powodować deadlock)
public synchronized void dodaj(String el) { lista.add(el); }

// 4. ReentrantLock — więcej kontroli
private final ReentrantLock lock = new ReentrantLock();
public void operacja() {
    lock.lock();
    try { /* sekcja krytyczna */ }
    finally { lock.unlock(); } // zawsze w finally!
}

// 5. volatile — widoczność między wątkami (nie atomowość!)
private volatile boolean dziala = true; // wątek zawsze czyta z pamięci
🚀 Virtual Threads — Java 21 (Project Loom)
▼

Virtual Threads to lekkie wątki zarządzane przez JVM (nie OS). Tradycyjny wątek OS kosztuje ~1MB RAM. Virtual Thread — kilka KB. Możesz tworzyć ich miliony.

Virtual Threads — Java 21
// Stworzenie Virtual Thread
Thread vt = Thread.ofVirtual().start(() -> obsluzRequest());

// ExecutorService z Virtual Threads — jeden thread per task!
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    // Każde zadanie = osobny virtual thread. Bez limit!
    IntStream.range(0, 100_000)
        .forEach(i -> executor.submit(() -> obsluzRequest(i)));
}

// ✅ Idealny do I/O-bound tasks (HTTP, DB, pliki)
// Gdy virtual thread czeka na I/O, JVM "parkuje" go
// i na tym samym OS thread obsługuje inny virtual thread.
// ❌ Nie dla CPU-bound tasks — tu lepszy ForkJoinPool

Clean Code — Zasady Czystego Kodu

Clean Code — Robert C. Martin
// ❌ Złe nazewnictwo
int d;           // co to?
void proc() {}  // jakie przetwarzanie?
boolean f(User u) {} // jaka flaga?

// ✅ Kod jako dokumentacja
int wiekUzytkownikaWLatach;
void obliczPodatekDochodowy() {}
boolean czyKlientMaAktywnaSubskrypcje(User klient) {}

// ❌ Magiczne liczby
if (pracownik.getWiek() > 65) { // co to 65? }

// ✅ Nazwane stałe
private static final int WIEK_EMERYTALNY = 65;
if (pracownik.getWiek() > WIEK_EMERYTALNY) { }

// ❌ Głęboka zagnieżdżoność (Pyramid of Doom)
if (user != null) {
    if (user.isActive()) {
        if (user.hasPermission("ADMIN")) {
            doSomething();
        }
    }
}

// ✅ Guard Clauses — Early Return
if (user == null) return;
if (!user.isActive()) return;
if (!user.hasPermission("ADMIN")) return;
doSomething(); // płasko i czytelnie!

// ✅ Małe metody — jedna metoda = jedno zadanie
// Zasada: metoda powinna zmieścić się na ekranie (max ~20 linii)

Najczęstsze Anty-wzorce w Javie

🚫
String concatenation w pętli
Każdy += tworzy nowy String. W pętli z 1000 iteracji = 1000 obiektów. Używaj StringBuilder lub String.join().
Wydajność
🚫
NullPointerException
Nie zwracaj null z metod — użyj Optional. Nie porównuj Stringów przez ==. Używaj Objects.requireNonNull() na wejściach.
Bezpieczeństwo
🚫
Brak equals/hashCode
Klasy używane w HashMap / HashSet MUSZĄ poprawnie implementować equals() i hashCode(). Używaj @Override.
Poprawność
🚫
Mutable statics
Mutable pola statyczne są współdzielone między wątkami bez synchronizacji. Preferuj niezmienne stałe lub użyj ThreadLocal.
