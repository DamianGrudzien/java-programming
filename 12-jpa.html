JPA & Hibernate

Java Persistence API — standard ORM w Javie. Hibernate to najpopularniejsza implementacja. Mapowanie obiektów na tabele, relacje, JPQL i Spring Data JPA.

JPA 3.1 Hibernate 6 Poziom: Średnio­zaawansowany

Encja — Mapowanie Klasy na Tabelę

Produkt.java — encja JPA 
@Entity
@Table(name = "produkty")  // nazwa tabeli w bazie
public class Produkt {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)  // AUTO_INCREMENT
    private Long id;

    @Column(name = "nazwa", nullable = false, length = 100)
    private String nazwa;

    @Column(precision = 10, scale = 2)
    private BigDecimal cena;

    @Column(name = "stan_magazynowy")
    private int stanMagazynowy;

    @CreationTimestamp  // Hibernate — automatycznie przy INSERT
    private LocalDateTime utworzono;

    @UpdateTimestamp    // Hibernate — automatycznie przy UPDATE
    private LocalDateTime zaktualizowano;

    @Version            // optimistic locking — zapobiega race condition
    private Long wersja;

    // Konstruktor bezargumentowy WYMAGANY przez JPA
    protected Produkt() {}

    public Produkt(String nazwa, BigDecimal cena, int stan) {
        this.nazwa = nazwa;
        this.cena = cena;
        this.stanMagazynowy = stan;
    }
    // gettery i settery...
}

@Entity
public class Zamowienie {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    // ✅ LAZY = załaduj użytkownika tylko gdy potrzebujesz
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "uzytkownik_id")  // klucz obcy w tabeli zamowienia
    private Uzytkownik uzytkownik;

    @Column(nullable = false)
    private BigDecimal lacznaKwota;
}
Użytkownik → Zamówienia (jeden do wielu) 
@Entity
public class Uzytkownik {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    // mappedBy = pole w Zamowienie które "posiada" relację
    @OneToMany(mappedBy = "uzytkownik",
               cascade = CascadeType.ALL,
               fetch = FetchType.LAZY,   // ✅ ZAWSZE lazy dla kolekcji!
               orphanRemoval = true)
    private List<Zamowienie> zamowienia = new ArrayList<>();

    // Helper methods — utrzymuj spójność obu stron relacji
    public void dodajZamowienie(Zamowienie z) {
        zamowienia.add(z);
        z.setUzytkownik(this);
    }
}
Produkt ↔ Kategoria (wiele do wielu) 
@Entity
public class Produkt {
    // ✅ Właściciel relacji definiuje tabelę łączącą
    @ManyToMany
    @JoinTable(
        name = "produkt_kategoria",
        joinColumns = @JoinColumn(name = "produkt_id"),
        inverseJoinColumns = @JoinColumn(name = "kategoria_id")
    )
    private Set<Kategoria> kategorie = new HashSet<>();
    // Set zamiast List — unika duplikatów i problemu z HHH-000
}

@Entity
public class Kategoria {
    @ManyToMany(mappedBy = "kategorie")
    private Set<Produkt> produkty = new HashSet<>();
}

Spring Data JPA — Repository

ProduktRepo.java 
// JpaRepository daje CRUD za darmo: save, findById, findAll, delete...
public interface ProduktRepo extends JpaRepository<Produkt, Long> {

    // Spring generuje SQL automatycznie z nazwy metody!
    List<Produkt> findByNazwaContainingIgnoreCase(String fraza);
    List<Produkt> findByCenaLessThanOrderByCenaAsc(BigDecimal max);
    Optional<Produkt> findByNazwaAndStanMagazynowyGreaterThan(String nazwa, int min);
    boolean existsByNazwa(String nazwa);
    long countByCenaLessThan(BigDecimal cena);

    // Własne zapytanie JPQL (obiektowe, nie SQL!)
    @Query("SELECT p FROM Produkt p WHERE p.cena BETWEEN :min AND :max")
    List<Produkt> znajdzWCenach(@Param("min") BigDecimal min,
                               @Param("max") BigDecimal max);

    // Natywny SQL gdy JPQL nie wystarczy
    @Query(value = "SELECT * FROM produkty WHERE stan_magazynowy = 0",
           nativeQuery = true)
    List<Produkt> znajdzWyprzedane();

    // Stronicowanie — Page zawiera metadane (total, pages...)
    Page<Produkt> findAll(Pageable pageable);
}

⚠️
Problem N+1 — najczęstszy błąd z JPA. Gdy ładujesz listę encji i dla każdej lazily ładujesz relację, generujesz N+1 zapytań SQL. Rozwiązanie: @EntityGraph lub JOIN FETCH w JPQL.
Rozwiązanie problemu N+1 
// ❌ Problem N+1 — 1 zapytanie na listę + N na każdego użytkownika
List<Zamowienie> zamowienia = repo.findAll();
zamowienia.forEach(z -> System.out.println(z.getUzytkownik().getImie()));

// ✅ JOIN FETCH — jedno zapytanie, ładuje wszystko naraz
@Query("SELECT z FROM Zamowienie z JOIN FETCH z.uzytkownik")
List<Zamowienie> znajdzZUzytkownikami();

// ✅ @EntityGraph — alternatywne podejście deklaratywne
@EntityGraph(attributePaths = {"uzytkownik"})
List<Zamowienie> findAll();

Transakcje w serwisie 
@Service
public class ZamowienieSerwis {

    // Metody @Transactional — wszystkie zmiany commitowane razem
    // lub rollback gdy wyjątek RuntimeException
    @Transactional
    public Zamowienie zloz(Long uzytId, List<Long> produktyIds) {
        var uzyt = uzytRepo.findById(uzytId)
            .orElseThrow(() -> new EntityNotFoundException("Brak użytkownika"));

        var produkty = prodRepo.findAllById(produktyIds);

        // Jeśli tu wyjątek — zmiany w bazie cofnięte automatycznie
        produkty.forEach(p -> p.zmniejszStan(1));

        return zamowRepo.save(new Zamowienie(uzyt, produkty));
    }

    // readOnly = true — optymalizacja dla odczytów (brak dirty checking)
    @Transactional(readOnly = true)
    public List<ZamowienieDto> znajdzDlaUzytkownika(Long id) {
        return zamowRepo.findByUzytkownikId(id)
            .stream().map(mapper::toDto).toList();
    }
}
